# Local 909 voicing variant

This version keeps the separate Ableton closed/open hats and changes the synthesized
snare, clap and shared reverb. It adds no sample recordings, playback state or reverb
buffers. The earlier hats-only checkout and firmware remain available separately.

- **Hats:** Decay approaches the recording's own envelope smoothly. At 127 the extra
  decay envelope is bypassed; the entire recording plays, adjusted for Tune, unless
  another hat chokes it. The source closed hat is 165.3 ms long at unity pitch, and
  the open hat is 777.8 ms. Decay cannot sustain beyond the recording. This is a
  sample/envelope limit rather than a RAM or processor limit.
- **Snare:** the existing 3 ms filtered-noise attack is enabled, and the wire-noise
  band widens from approximately 1–6.5 kHz to 0.7–10 kHz. Noise gain is adjusted to
  retain approximately the earlier noise power. Tune, Tone, Snappy and Decay keep
  their existing assignments; Tone still controls the noise decay.
- **Clap:** band-pass Q is reduced from 2 to 1, with gain compensation before Drive.
  The four attack bursts now have gaps of approximately 9, 13 and 17 ms instead of
  three identical 12 ms gaps. Tail, Tune, Level and Drive remain available.
- **Reverb:** the first left allpass buffer now diffuses the input before the four
  combs. The remaining stages use true allpass feedback, avoiding the original
  extra spectral gain. This changes the shared reverb for every part sent to it;
  its default send amounts and controls are unchanged. The 12-bit feedback texture
  remains. This is a listening candidate, not a promise of complete removal of
  the small reverb's metallic character.

The project data format and control indices are unchanged. Built-in break loops
are regenerated by the changed 909, so their snare sound changes too.

## Target build

`build/x0x-1.1.0-voicing.fwsc` is a local package, built with JieLi clang 4.0.1
(`jieli-linux-toolchains-20260730.1`) and the expected AC79 SDK assets.

| Region | Used | Capacity | Free |
| --- | ---: | ---: | ---: |
| App flash | 543248 B | 581564 B | 38316 B |
| RAM .data + .bss | 97704 B | 98304 B | 600 B |
| Buffer pool | 335808 B | 344064 B | 8256 B |

RAM and pool use match the hats-only version. The app is 224 bytes larger,
including its version label. RAM remains tight: only 64 pool bytes are beyond the
required 8192-byte reserve. Flash, RAM, pool, HAL and single-precision build checks
pass. Source sample data remain 173997 bytes including the mu-law decode table.

## Verification and listening

- Hat tests verify lossless PCM playback, full tails at Decay 127, a smooth change
  from 126 to 127, pitch-adjusted lifetime and reciprocal choke.
- Voicing tests verify the short snare attack, wider noise pass band, body decay,
  unequal clap-burst spacing, control extremes and retriggers. Reverb impulse
  tests check stereo energy, finite output and decaying tails at control extremes.
- Both suites pass with AddressSanitizer. Stereo/mono consistency tests pass.
- 198 unchanged-voice cases still match 9W9. The 192 cases involving deliberately
  changed voices/envelopes or reverb are explicitly skipped by that old-sound
  comparison and covered by the local regression tests. The full-kit demo also
  checks that its 16-bit WAV export does not clip.
- `build/emulator/voicing-before.wav` and `voicing-after.wav` capture the real
  compiled packages with the same MIDI sequence and factory mixer: two snares,
  then two claps. `voicing-ab.wav` joins them with a short silent gap. No gain
  normalization is applied to these recordings.
- `build/emulator/hat-max-ab.wav` compares the previous and new closed hat at
  maximum Decay, set through the emulated panel. `hat-max-panel.png` shows that
  setting. The separate hats-only firmware remains in the original checkout.

Emulator logs and RAM checks are in `build/emulator/`. Physical hardware listening,
cache/flash timing and exhaustive song stress tests remain unverified. The emulator
logs unmodeled P33 power-management register accesses; its timing is not a physical
hardware benchmark. The pre-existing signed-shift warning in `fastmath.h` remains
outside this sound change.

The final batch run uses `--ram 524288`, exercises max hat Decay through KNOB1,
hat playback/choke, snare and clap, and completes 2.5 seconds without a halt:
102912 audio frames, no clipped samples and `eng_guard_count` zero. The panel
capture confirms CH Decay 127 with Tune 64. The RAM snapshot leaves the region
above 512 KiB untouched.

## Local build environment

The reusable Apple Container is `fm1-jieli-drums-k612`. Start it, then run:

```sh
container start fm1-jieli-drums-k612
container exec fm1-jieli-drums-k612 python3 tools/build.py --release 1.1.0-voicing
```

This checkout is mounted at `/work`; the toolchain and SDK are read-only mounts,
and `JIELI_DOCKER=0` runs the compiler directly in Linux x86-64. The per-container
Linux 6.12.47 kernel works with this Mac's Rosetta version, as described in the
[Apple Container issue](https://github.com/apple/container/issues/1142).
